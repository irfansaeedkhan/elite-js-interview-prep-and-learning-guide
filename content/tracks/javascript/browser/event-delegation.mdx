<TopicDefinition>

If someone asks me what event delegation is, I'd say it's one listener on a parent doing the job of a hundred listeners on children. Instead of attaching a handler to every row, button, or cell, you attach a single handler to their shared parent and let the event come to you.

Interviewers care because it tests whether you understand bubbling, not just addEventListener. The handler has to work out which child was actually clicked, and that is where people slip up. The click rarely lands exactly on the element you expect. It lands on an icon, a span, or a nested SVG inside it.

The senior nuance is knowing the limits. Delegation only works for events that bubble, so focus and blur need a different approach. And a delegated handler that is too broad, say one giant listener on document catching everything, turns into a guessing game. Delegate to the nearest stable parent, and check that the match actually belongs to it.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="One listener for a whole list" language="javascript">
{`const list = document.querySelector('#todo-list');

list.addEventListener('click', (event) => {
  const button = event.target.closest('button[data-action]');
  if (!button || !list.contains(button)) return;

  if (button.dataset.action === 'delete') {
    button.closest('li').remove();
  }
  if (button.dataset.action === 'done') {
    button.closest('li').classList.toggle('done');
  }
});`}
</CodeExample>

<CodeExample title="The nested-icon trap" language="javascript">
{`// Broken: clicking the icon inside the button misses the check.
// event.target is the <svg>, not the <button>.
list.addEventListener('click', (event) => {
  if (event.target.tagName === 'BUTTON') {
    console.log('delete');
  }
});

// Fixed: closest() walks up from wherever the click landed.
list.addEventListener('click', (event) => {
  const button = event.target.closest('button[data-action]');
  if (button) {
    console.log(button.dataset.action);
  }
});`}
</CodeExample>

<CodeExample title="Dynamically added items just work" language="javascript">
{`// The listener is attached once, before any of these rows exist.
const list = document.querySelector('#todo-list');
list.addEventListener('click', (event) => {
  const item = event.target.closest('li');
  if (item && list.contains(item)) {
    console.log('clicked:', item.textContent);
  }
});

// No re-binding needed. This row is covered the moment it is added.
const row = document.createElement('li');
row.textContent = 'Added later, still handled';
list.append(row);`}
</CodeExample>

Say the three steps out loud: one listener on the parent, closest() to find the real element, contains() to prove it belongs to this container.
</Callout>

<TopicTab value="indepth">

The algorithm is three steps, and interviewers want to hear all three. First, attach one listener to a stable parent that exists when the page loads. Second, in the handler, use `event.target.closest(selector)` to find the child you care about, starting from wherever the click actually landed. Third, confirm the match belongs to your container with `container.contains(match)` and bail out early if it does not.

The `contains()` check matters because `closest()` walks up past your container. If your list is nested inside another list, or a click bubbles from a widget you did not build, `closest()` can return a button that is not yours. The guard is one line and it is the difference between a correct answer and a nearly correct one.

Two more things senior rounds probe. One, `stopPropagation()` in a child handler silences every delegated parent above it, so a child that stops propagation breaks delegation silently. Two, delegation is not automatically faster. For a handful of static buttons, direct listeners are simpler and clearer. Delegation earns its keep with many similar children, or children that come and go.

<Callout type="interview">
Lead with the mechanism, not the slogan: "Clicks bubble, so the parent hears them. closest() finds the real button, contains() proves it is mine." Then name the trap: a raw event.target check breaks on nested icons.
</Callout>

<Callout type="gotcha">
Non-bubbling events never reach a delegated parent. focus and blur need focusin and focusout, and mouseenter and mouseleave have bubbling cousins mouseover and mouseout, which also fire when moving between children, so direct listeners or a capture-phase listener are usually cleaner.
</Callout>

</TopicTab>

  const node = {
    tagName: tag,
    dataset: action === undefined ? {} : { action },
    parent,
    closest() {
      let current = this;
      while (current) {
        if (current.tagName === 'BUTTON' && current.dataset.action !== undefined) {
          return current;
        }
        current = current.parent;
      }
      return null;
    },
    contains(other) {
      let current = other;
      while (current) {
        if (current === this) return true;
        current = current.parent;
      }
      return false;
    },
  };
  return node;
}

  // your code here
