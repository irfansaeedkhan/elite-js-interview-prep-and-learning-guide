<TopicDefinition>

If someone asks me what fetch is, I'd say it's the browser's built-in way to make HTTP requests — you call `fetch(url)` and get back a promise that resolves to a Response. The part people miss is that the promise resolving does **not** mean the request succeeded. It only means the server answered.

Interviewers care about this topic because the error handling is backwards from what most people expect. A 404 or a 500 still resolves the promise — fetch only rejects when no response arrives at all, like being offline or hitting a CORS block. So the real skill is the two-step habit: check `response.ok` first, then read the body. And since fetch has no timeout option, senior rounds always ask how you'd stop a request that hangs — that's `AbortController`.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="The shape of a correct fetch" language="javascript">
{`async function getUser(id) {
  const response = await fetch(\`/api/users/\${id}\`);
  // Step 1: the promise resolved — but did the request SUCCEED?
  if (!response.ok) {
    throw new Error(\`HTTP \${response.status}\`);
  }
  // Step 2: only now read the body (this await is easy to forget)
  return response.json();
}

// A 404 here throws from OUR check, not from fetch:
// getUser(999) → Error: HTTP 404
// Offline here rejects from fetch itself → caught by try/catch`}
</CodeExample>

<CodeExample title="POST with JSON, and reading the error body" language="javascript">
{`async function createUser(name) {
  const response = await fetch('/api/users', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name }), // fetch does NOT stringify for you
  });

  if (!response.ok) {
    // Error responses often carry a useful JSON message — read it before throwing
    const errorBody = await response.json().catch(() => ({}));
    throw new Error(errorBody.message ?? \`HTTP \${response.status}\`);
  }
  return response.json();
}`}
</CodeExample>

<CodeExample title="Timeout and manual cancel with AbortController" language="javascript">
{`// One-liner timeout: rejects with TimeoutError after 5 seconds
const response = await fetch('/api/slow', {
  signal: AbortSignal.timeout(5000),
});

// Manual cancel: search-as-you-type, abort the stale request
const controller = new AbortController();
try {
  const res = await fetch(\`/api/search?q=\${query}\`, { signal: controller.signal });
  if (!res.ok) throw new Error(\`HTTP \${res.status}\`);
  return res.json();
} catch (err) {
  if (err.name === 'AbortError') return; // cancelled on purpose, not a failure
  throw err;
}
// When the user types the next character:
controller.abort();`}
</CodeExample>

<TopicTab value="indepth">

### What to focus on

- The mental model: fetch resolving means "the server answered," not "the request succeeded"
- The two-step habit: `response.ok` check first, body read second — in that order, every time
- The three reject cases: network failure, CORS block, and abort — everything else resolves

### Traps interviewers reach for

- **"Why didn't my catch run on a 404?"** — because 404 resolves. The catch only sees network failures and aborts.
- **"Why is my data undefined?"** — usually a missing second await: `const data = response.json()` without awaiting it, so `data` is still a promise and `data.name` is undefined.
- **"Why did the second .json() fail?"** — the body stream is consumed on first read. Clone first if you need two reads.
- **"Why does my request hang forever?"** — fetch has no timeout. A hung server means a hung request until you add an AbortSignal.
- **CORS errors look like network errors** — a CORS block rejects with an opaque TypeError, and no frontend code can fix it; the server has to allow the origin.

### Senior follow-ups

Be ready to describe your production wrapper: ok check, timeout signal, error-body parsing, and a 401 path that refreshes auth or redirects to login, distinct from a 500 path that just reports. Know that fetch can't report upload progress (no `onprogress` like XMLHttpRequest), that credentials default to same-origin, and that `AbortSignal.any()` combines a timeout signal with a manual cancel signal into one.
