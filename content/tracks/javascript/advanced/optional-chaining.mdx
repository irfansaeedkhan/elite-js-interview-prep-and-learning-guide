<TopicDefinition>

If someone asks what optional chaining is, I'd say it's how you read deep into data you don't control without crashing. API responses, user objects, config files — any of them can arrive with a piece missing, and `user?.address?.city` gives you `undefined` where plain `user.address.city` throws.

What interviewers actually probe is the pair it travels with: `??`. Optional chaining keeps you from crashing on missing data, and nullish coalescing gives you a fallback — but only when the value is `null` or `undefined`. That's the trap `||` sets: it treats `0`, an empty string, and `false` as missing too, so a real setting gets replaced by its default.

In senior rounds you might hear about the one hard rule: never mix `??` with `||` or `&&` without parentheses. The language won't guess your grouping — it throws a SyntaxError and the whole file refuses to run. One pair of parens is the entire fix.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Safe deep access: properties, brackets, and calls" language="javascript">
{`const user = { name: 'Ada' };

// missing piece? undefined, no crash
console.log(user?.address?.city); // undefined

// same idea for bracket access and method calls
const key = 'city';
console.log(user?.address?.[key]); // undefined
console.log(user.sendEmail?.('hi')); // undefined — method does not exist, never called

// compare with the old way: three guards for one read
const city = user && user.address && user.address.city;
console.log(city); // undefined`}
</CodeExample>

<CodeExample title="?? keeps real values, || replaces them" language="javascript">
{`// a settings panel where 0, '' and false are legitimate choices
const settings = { volume: 0, nickname: '', darkMode: false, theme: null };

console.log(settings.volume ?? 50);   // 0 — kept
console.log(settings.volume || 50);   // 50 — wrongly replaced

console.log(settings.nickname ?? 'Guest'); // '' — kept
console.log(settings.darkMode ?? true);    // false — kept
console.log(settings.theme ?? 'light');    // light — null is genuinely missing

// the pair together: safe read, then a fallback
const city = user?.address?.city ?? 'Unknown city';
console.log(city); // Unknown city`}
</CodeExample>

<CodeExample title="Short-circuit skips the rest of the chain" language="javascript">
{`let calls = 0;
const api = null;

// api is null, so nothing after the first ?. runs —
// the callback is never even built, let alone called
const result = api?.fetch?.(() => { calls += 1; });
console.log(calls, result); // 0 undefined

// same rule for a method that returns undefined:
// ?? looks at the RETURN value, not at whether the method exists
const svc = { getName() { return undefined; } };
console.log(svc.getName?.() ?? 'fallback'); // fallback — method ran, returned undefined`}
</CodeExample>

<CodeExample title="??= assigns only when the value is nullish" language="javascript">
{`const config = { timeout: null, retries: 0 };

// timeout is null, so it gets the default; retries is 0, so it keeps it
config.timeout ??= 5000;
config.retries ??= 3;
console.log(config.timeout, config.retries); // 5000 0

// handy for filling in options objects without clobbering real values
function connect(options) {
  options.timeout ??= 5000;
  options.retries ??= 3;
  return options;
}
console.log(connect({ timeout: 1000 })); // { timeout: 1000, retries: 3 }`}
</CodeExample>

<TopicTab value="indepth">

<Callout type="gotcha">
Mixing `??` with `||` or `&&` is a SyntaxError, not a runtime bug — the file never runs at all. `a ?? b || c` fails to parse; `(a ?? b) || c` is what you meant. This is the one mistake that stops your whole file before a single line executes.
</Callout>

<Callout type="gotcha">
`?.` reads only. `user?.profile?.name = 'Ada'` is invalid — check with `?.` first, then assign through the plain path: `if (user?.profile) { user.profile.name = 'Ada'; }`.
</Callout>

<Callout type="tip">
Chain the data you don't control — API payloads, parsed JSON, third-party objects. For objects your own code built, a missing property is a bug worth failing fast on, not something to paper over with `?.` on every line.
</Callout>

<CodeExample title="The two classic one-line traps" language="javascript">
{`// trap 1: || eats a real value — the volume bug
const volume = 0;
console.log(volume || 50); // 50 — the user's 0 is gone
console.log(volume ?? 50); // 0 — the user's choice survives

// trap 2: ?? needs parens next to || or &&
// const x = a ?? b || c; — SyntaxError, whole file dead
const x = (null ?? 'a') || 'b'; // a — parens say what you meant
console.log(x);`}
</CodeExample>
