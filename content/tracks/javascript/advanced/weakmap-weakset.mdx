<TopicDefinition>

If someone asks what a WeakMap is, I'd say it's a Map with one difference: it doesn't keep its keys alive. You attach data to an object, and the moment nothing else points at that object, the entry can disappear with it. A WeakSet is the same idea for membership. It remembers that an object was in the set, without keeping it alive.

Interviewers bring these up when they want to know whether you think about memory. The classic story is DOM nodes. You store metadata about elements in a normal Map, remove the elements from the page, and the Map still holds every one of them. That's a leak, and it grows with every re-render. A WeakMap lets the metadata die with the element, so there is nothing to clean up.

The trade-off is that you give up the conveniences: no size, no iteration, no listing keys. That isn't an oversight, it's the point. A WeakMap can't promise you a list of entries that might vanish at any moment. And you can never observe the collection happening, so never write code that depends on when an entry disappears.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Private data, the pre-# way" language="javascript">
{`const privateData = new WeakMap();

class User {
  constructor(name, password) {
    this.name = name;
    privateData.set(this, { password });
  }
  checkPassword(guess) {
    return privateData.get(this).password === guess;
  }
}

const u = new User('alice', 's3cr3t');
console.log(u.name);                  // 'alice' — public
console.log(u.password);              // undefined — nothing on the instance
console.log(u.checkPassword('s3cr3t')); // true`}</CodeExample>

<CodeExample title="A cache that leaks vs one that doesn't" language="javascript">
{`// A Map keeps every key alive — a cache that only grows.
const leakyCache = new Map();
function getStatsLeaky(user) {
  if (!leakyCache.has(user)) leakyCache.set(user, { posts: 42 });
  return leakyCache.get(user);
}

// A WeakMap lets the entry die with the user object.
const cache = new WeakMap();
function getStats(user) {
  if (!cache.has(user)) cache.set(user, { posts: 42 });
  return cache.get(user);
}

let user = { name: 'bob' };
getStats(user);
user = null; // the WeakMap entry can now be collected; the Map entry cannot`}</CodeExample>

<CodeExample title="WeakSet: marking objects you have seen" language="javascript">
{`// A WeakSet marks objects. It stores no data about them,
// and the mark disappears when the object does.
const processed = new WeakSet();

function process(order) {
  if (processed.has(order)) return 'already processed';
  processed.add(order);
  return 'processing ' + order.id;
}

const order = { id: 101 };
console.log(process(order)); // 'processing 101'
console.log(process(order)); // 'already processed'`}</CodeExample>

<CodeExample title="The traps, all in one place" language="javascript">
{`const wm = new WeakMap();

// 1. Keys must be objects — a primitive throws.
try {
  wm.set('user', 1);
} catch (e) {
  console.log(e.message); // 'Invalid value used as weak map key'
}

// 2. There is no size and no way to list entries.
console.log(wm.size);        // undefined
console.log(typeof wm.keys); // 'undefined'

// 3. A WeakMap is not iterable.
try {
  for (const entry of wm) {
    // never runs
  }
} catch (e) {
  console.log(e instanceof TypeError); // true
}`}</CodeExample>

<TopicTab value="indepth">

<Callout type="gotcha">
You cannot observe garbage collection. There is no test that proves an entry disappeared, because the engine collects when it wants to. Test the contract instead: primitives throw, there is no size, and the entry is there while the key is alive.
</Callout>

<Callout type="tip">
If you need to list entries, count them, or keep them after the key is gone, you picked the wrong collection. That job belongs to a Map. A WeakMap is only for data that should die with its key.
</Callout>

### Which collection when

- **Map** — general key-value storage, any key type, iterable, has a size.
- **WeakMap** — metadata, private data, or a cache tied to an object's lifetime.
- **Set** — unique values you need to list or count.
- **WeakSet** — marking objects (visited, processed, seen) without keeping them alive.

<CodeExample title="Senior nuance: a value can point back at its own key" language="javascript">
{`const wm = new WeakMap();
const key = { id: 1 };

// The value references its own key, and that still does not
// keep the key alive. WeakMap entries are ephemerons: the value
// is only reachable through the key, so it cannot rescue the key.
wm.set(key, { owner: key });
console.log(wm.get(key).owner === key); // true`}</CodeExample>

### Senior follow-ups

Be ready to say why `#` private fields replaced the WeakMap pattern in modern code, and when you'd still reach for a WeakMap: when the data belongs to an object you don't own, like a DOM node. And remember that a value referencing its own key never keeps the key alive, so a self-referential value is not a leak.
