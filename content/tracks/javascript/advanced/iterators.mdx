<TopicDefinition>

If someone asks what iterators are, I'd say they're the quiet contract underneath `for...of`, spread, and destructuring. An **iterable** is anything with a `[Symbol.iterator]()` method — arrays, strings, Maps, Sets. An **iterator** is the thing that method hands back, with a `next()` that returns `{ value, done }` one pair at a time.

The trap interviewers love is the plain object: `for (const v of { a: 1 })` throws a `TypeError`, because objects have no default iteration order. If you want values from an object, you go through `Object.values()` or `Object.entries()` first.

Senior rounds usually go to the single-use rule — an iterator is consumed once, and a second loop over the same iterator gives you nothing — and to `return()`, the cleanup hook that runs when you `break` out of a `for...of` early.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="An iterator, called by hand" language="javascript">
{`const it = ['a', 'b'].values();

console.log(it.next()); // { value: 'a', done: false }
console.log(it.next()); // { value: 'b', done: false }
console.log(it.next()); // { value: undefined, done: true }

// for...of is just this loop, automated:
// it calls [Symbol.iterator](), then next() until done is true.`}
</CodeExample>

<CodeExample title="Making your own object iterable" language="javascript">
{`const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from;
    return {
      next: () =>
        current <= this.to
          ? { value: current++, done: false }
          : { value: undefined, done: true },
    };
  },
};

console.log([...range]); // [1, 2, 3]
console.log([...range]); // [1, 2, 3] again — a fresh iterator each time
for (const n of range) console.log(n); // 1, 2, 3`}
</CodeExample>

<CodeExample title="for...of vs for...in — values vs keys" language="javascript">
{`const arr = ['x', 'y'];
arr.extra = '!';

for (const v of arr) console.log('of:', v);
// of: x / of: y — values only, extra property ignored

for (const k in arr) console.log('in:', k);
// in: 0 / in: 1 / in: extra — string keys, including the extra one

const m = new Map([['a', 1], ['b', 2]]);
for (const [k, v] of m) console.log('map:', k, v);
// map: a 1 / map: b 2 — Maps iterate [key, value] pairs`}
</CodeExample>

<Callout type="interview">
When they ask "iterable or iterator?", answer with the two contracts: **iterable** has `[Symbol.iterator]()`, **iterator** has `next()`. Then prove it with `arr.values().next()`.
</Callout>

<TopicTab value="indepth">

<CodeExample title="Trap 1: plain objects are not iterable" language="javascript">
{`try {
  for (const v of { a: 1 }) {
    console.log(v);
  }
} catch (error) {
  console.log(error.constructor.name); // TypeError — not iterable
}

// The fix: turn it into an array first
console.log(Object.values({ a: 1 })); // [1]
console.log(Object.entries({ a: 1 })); // [['a', 1]]`}
</CodeExample>

<CodeExample title="Trap 2: an iterator is single-use" language="javascript">
{`function* gen() {
  yield 1;
  yield 2;
}

const g = gen();
console.log([...g]); // [1, 2]
console.log([...g]); // [] — already consumed, nothing left

// Same trap hides in a custom iterable that returns this:
// [Symbol.iterator]() { return this; } shares one position,
// so the second loop over the SAME object comes back empty.
// Return a fresh iterator object each call instead.`}
</CodeExample>

<CodeExample title="Trap 3: break triggers cleanup via return()" language="javascript">
{`function* withCleanup() {
  try {
    yield 1;
    yield 2;
    yield 3;
  } finally {
    console.log('cleaned up');
  }
}

for (const v of withCleanup()) {
  console.log(v); // 1
  break;          // loop calls return() — finally runs
}
// cleaned up`}
</CodeExample>

### Senior follow-ups

- **Iterator helpers (ES2025, Baseline 2025):** `Iterator.from(iterable)` gives you `.map()`, `.filter()`, `.take()`, and `.drop()` directly on iterators — lazy pipelines without building an intermediate array. `Iterator.from([1, 2, 3, 4]).map(x => x * 2).take(2)` yields `2, 4` and never touches the rest.
- **Async iteration:** `for await...of` and `[Symbol.asyncIterator]()` are the same two contracts, async — worth a sentence if the role involves streams or paginated APIs.
- **When not to hand-roll an iterator:** if a generator function can express the sequence, use it — the engine writes `next()` and `return()` for you. Hand-write only when the iteration state lives outside the function (a cursor, a socket).
