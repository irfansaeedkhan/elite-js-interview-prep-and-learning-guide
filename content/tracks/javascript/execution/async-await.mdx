<TopicDefinition>

If someone asks what async/await is, I'd say it's syntactic sugar over promises — a way to write asynchronous code so it reads top to bottom. You mark a function `async`, and inside it you can `await` a promise, which means "pause here until this settles and give me the value."

The part interviewers care about most is the word **pause**. `await` pauses **your function**, not the whole program. The rest of the code keeps running, and your function resumes later as a microtask. That's the trick behind every output-order question they ask on this topic.

For senior rounds, remember this: every `await` in a row adds up. Three awaits for three independent API calls means three sequential round trips. Interviewers will show you that waterfall and expect you to reach for `Promise.all`.

</TopicDefinition>

<CodeExample title="The basic shape" language="javascript">
{`async function getUser(id) {
  try {
    const res = await fetch(\`/api/users/\${id}\`);
    if (!res.ok) throw new Error(\`HTTP \${res.status}\`);
    return await res.json();
  } catch (err) {
    console.error('Failed to load user:', err.message);
    return null;
  }
}

// async always returns a promise — even this:
async function five() { return 5; }
five().then(v => console.log(v)); // 5`}
</CodeExample>

<CodeExample title="The sequential trap and the parallel fix" language="javascript">
{`// SLOW: 200ms + 200ms + 200ms = ~600ms
async function slow(ids) {
  const results = [];
  for (const id of ids) {
    results.push(await fetchStats(id)); // each await waits for the last
  }
  return results;
}

// FAST: all three start at once, ~200ms total
async function fast(ids) {
  return await Promise.all(ids.map(id => fetchStats(id)));
}`}
</CodeExample>

<CodeExample title="The forEach trap" language="javascript">
{`// BROKEN: forEach doesn't wait for async callbacks
async function broken(ids) {
  ids.forEach(async (id) => {
    await saveItem(id); // fires, but nobody waits
  });
  console.log('done'); // prints before any save finishes
}

// FIXED — serial: for...of
async function serial(ids) {
  for (const id of ids) {
    await saveItem(id);
  }
}

// FIXED — parallel: Promise.all
async function parallel(ids) {
  await Promise.all(ids.map((id) => saveItem(id)));
}`}
</CodeExample>

<TopicTab value="indepth">

### How await actually works

When execution reaches `await promise`, the function is suspended and its remaining code is scheduled as a **microtask**. Microtasks run after the current synchronous code finishes, before timers and I/O. That's why:

```js
async function main() {
  console.log('A');
  await Promise.resolve();
  console.log('B');
}
main();
console.log('C');
// A, C, B — 'B' waits for the microtask queue
```

### await on a non-promise

`await 42` is legal and evaluates to `42` — the value is wrapped via `Promise.resolve`. It never throws for this reason.

### Promise.all vs Promise.allSettled

- `Promise.all` **rejects fast**: the first rejection wins, but the other promises keep running in the background — their results are just discarded.
- `Promise.allSettled` waits for everything and hands you `{ status: 'fulfilled', value }` or `{ status: 'rejected', reason }` per item. Use it when every result matters even if some fail.

### Where try/catch fits

`await` throws the rejection reason inside the async function, so `try/catch` works naturally. But watch the reverse direction: an async function you call **without** await and **without** `.catch()` produces an unhandled rejection — in Node.js that can crash the process.

### Senior follow-ups to rehearse

- Convert a `.then()` chain into equivalent async/await (and back).
- Add a timeout around a promise with `Promise.race`.
- Why awaiting in a loop is sometimes correct — when each step genuinely depends on the previous one (e.g., paginated cursors).
