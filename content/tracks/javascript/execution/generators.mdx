<TopicDefinition>

If someone asks me what a generator is, I'd say it's a function you can pause in the middle and pick up later. You write it with `function*` and `yield` inside it, and every `yield` is a stopping point where the function hands a value out and waits.

Interviewers care because generators test whether you really understand laziness and control flow, not just syntax. Calling the function does not run a single line of it. The body only starts when you call `next()`, and it only runs as far as the next `yield`. That surprises people who expect a function call to mean execution.

The senior nuance is that communication runs both ways. `next()` does not just pull a value out. `next(value)` pushes a value back in, landing as the result of the paused `yield` expression. And a generator is single-use: once it reports `done: true`, it stays done, so a fresh sequence means calling the function again.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Pause and resume, step by step" language="javascript">
{`function* countUp() {
  yield 1;
  yield 2;
  yield 3;
}

const counter = countUp(); // nothing has run yet
console.log(counter.next()); // { value: 1, done: false }
console.log(counter.next()); // { value: 2, done: false }
console.log(counter.next()); // { value: 3, done: false }
console.log(counter.next()); // { value: undefined, done: true }

// A finished generator stays finished.
console.log(counter.next()); // { value: undefined, done: true }`}
</CodeExample>

<CodeExample title="Lazy sequences: infinite is fine when nobody asks for all of it" language="javascript">
{`function* naturals() {
  let n = 1;
  while (true) {
    yield n;
    n += 1;
  }
}

// This never builds an infinite array. Values are pulled one at a time,
// so stopping after five is cheap.
for (const n of naturals()) {
  if (n > 5) break;
  console.log(n); // 1, 2, 3, 4, 5
}`}
</CodeExample>

<CodeExample title="Two-way traffic with next(value)" language="javascript">
{`function* greet() {
  const name = yield 'What is your name?';
  yield 'Hello, ' + name + '!';
}

const g = greet();
console.log(g.next('nobody').value); // 'What is your name?'
// The first next() argument is ignored: no yield is paused yet.
console.log(g.next('Ada').value); // 'Hello, Ada!'
// 'Ada' landed as the result of the paused yield expression.`}
</CodeExample>

<CodeExample title="yield* delegates, and captures the return value" language="javascript">
{`function* inner() {
  yield 1;
  return 'inner-done';
}

function* outer() {
  // yield* yields every value from inner(), then evaluates to
  // inner's return value. A plain for...of over inner() would
  // never show you 'inner-done' at all.
  const result = yield* inner();
  yield result;
}

console.log([...outer()]); // [1, 'inner-done']`}
</CodeExample>

<OutputPrediction
  title="The return value hides from for...of"
  expected="2 1 lift off"
  hint="Drive it by hand with next(): what does the third call return?"
  explanation="Manual next() calls show the return value: after 2 and 1, the final call returns 'lift off' with done set to true. But for...of stops at done: true without reading that value, so [...countdown(2)] is just [2, 1]."

  while (n > 0) {
    yield n;
    n -= 1;
  }
  return 'lift off';
}

out.push(g.next().value);
out.push(g.next().value);
out.push(g.next().value);
console.log(out.join(' '));`}
/>

<Callout type="tip">
Say it out loud in one breath: calling gives you a paused object, next() runs to the next yield, next(value) talks back, and done means finished forever.
</Callout>

<TopicTab value="indepth">

The mental model is pull, not push. An array hands you everything up front. A generator hands you one value each time you ask, and does no work between asks. That is why an infinite generator is safe: the loop inside it only advances when something calls `next()`, and a `for...of` with a `break` simply stops asking.

Three rules keep you out of trouble in interviews. First, a generator is single-use. Exhausting it does not reset it, and calling `next()` again just keeps returning `done: true`. A fresh sequence means a fresh call to the generator function. Second, `yield` only works directly inside the `function*` body. A `yield` inside a nested callback or a `forEach` is a syntax error, because that callback is an ordinary function, not the generator. Third, `yield` is an expression, not just a statement. That is the whole mechanism behind `next(value)`: the paused `yield` evaluates to whatever the caller sent in.

Two more tools round out the picture. `return(value)` on the generator object ends it early, as if the body had returned. `throw(error)` injects an exception at the paused `yield`, so a `try...catch` inside the generator can handle it. And for async work, the shape changes: `async function*` plus `for await...of` is the async counterpart, with promises instead of plain values. Do not mix the two up in an answer.

<Callout type="interview">
Lead with laziness, then prove it: "Calling it runs nothing. The first next() starts the body, each yield pauses it, and the argument to the first next() is ignored." Then name the trap: the return value vanishes in for...of.
</Callout>

<Callout type="gotcha">
A finished generator does not rewind, and a return value paired with done: true is invisible to for...of and spread. If a test or an interviewer expects the return value, drive the generator by hand with next() or capture it through yield* delegation.
</Callout>

</TopicTab>
