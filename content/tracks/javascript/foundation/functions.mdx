<TopicDefinition>

If an interviewer asks how functions work in JavaScript, I'd start here: a function is a reusable block of code, and there are four ways to write one — a declaration (`function f() {}`), an expression (`const f = function() {}`), an arrow (`const f = () => {}`), and the method shorthand (`greet() {}` inside an object).

The question that follows is almost always about **arrows**: they don't get their own `this`, their own `arguments`, or a `prototype`. They borrow `this` from wherever they were defined. That's the feature when you write `.map(x => x * 2)` — and the trap when you write an object method as an arrow.

One senior-level framing worth having: **callable vs constructable**. Regular functions are both — you can call them and `new` them. Arrows are callable only (`new` throws). Class constructors are the reverse — constructable only.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Declaration vs expression vs arrow" language="javascript">
{`// Declaration: hoisted, callable before this line
declared(); // works

// Expression / arrow: TDZ until the line runs
// arrow(); // ReferenceError: Cannot access 'arrow' before initialization

function declared() { return 'hoisted'; }
const arrow = () => 'not hoisted';`}
</CodeExample>

<CodeExample title="The arrow-method trap" language="javascript">
{`const counter = {
  count: 0,
  // WRONG: arrow takes this from the enclosing scope, not counter
  increment: () => { this.count++; },
  // RIGHT: method shorthand gets this = counter
  bump() { this.count++; },
};`}
</CodeExample>

<CodeExample title="Implicit return with objects" language="javascript">
{`// WRONG: braces are a block body, { name: name } is a label — returns undefined
const makeUser = (name) => { name: name };

// RIGHT: wrap the object in parentheses
const makeUser2 = (name) => ({ name: name });
console.log(makeUser2('ada')); // { name: 'ada' }`}
</CodeExample>

<CodeExample title="Default and rest params" language="javascript">
{`function greet(name = 'guest') {
  return \`hi \${name}\`;
}
greet();      // 'hi guest'
greet('ada'); // 'hi ada'

// Rest params replace the arguments object (arrows have none)
const sum = (...numbers) => numbers.reduce((a, b) => a + b, 0);
sum(1, 2, 3); // 6`}
</CodeExample>

When an interviewer says "functions," lead with the **four forms** — declaration, expression, arrow, method — then state the arrow rule: **no own `this`, no `arguments`, no `new`**.
</Callout>

### Named function expressions

Anonymous functions show up as `(anonymous)` in stack traces. Naming the expression costs nothing and makes debugging real:

<CodeExample title="Named function expressions" language="javascript">
{`const factorial = function fact(n) {
  return n <= 1 ? 1 : n * fact(n - 1); // fact is visible only inside itself
};`}
</CodeExample>

The inner name `fact` is scoped to the function body — handy for recursion without depending on the outer variable.

### IIFEs are scope, not magic

An immediately-invoked function expression just runs code in its own scope. Modules and block scoping made them rare, but you'll still read them in older codebases:

<CodeExample title="IIFE" language="javascript">
{`(function () {
  const secret = 'not global';
  // ... setup work ...
})();`}
</CodeExample>

### Senior nuance: arrow class fields cost memory

`handler = () => {}` as a class field is "auto-bound," but the arrow is created **per instance**, not once on the prototype. In hot paths with thousands of instances, a prototype method plus an explicit bind in the constructor can be leaner.

### Useful built-ins

- `fn.length` — number of declared parameters (rest params don't count)
- `fn.name` — the function's name, even when inferred from a variable
- `fn.call(thisArg, ...args)` / `fn.apply(thisArg, args)` / `fn.bind(thisArg)` — control `this` (no effect on arrows)
