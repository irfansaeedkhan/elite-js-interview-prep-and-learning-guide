interviewQuestions:
  - id: this-1
    question: How is this determined in JavaScript?
    answer: By call site — as a method, plain function, constructor, call/apply/bind, or arrow (lexical). Not by where the function was written.
    difficulty: medium
  - id: this-2
    question: What is this in an arrow function?
    answer: Lexically inherited from the enclosing scope at definition time. It cannot be changed with call or bind.
    difficulty: medium
  - id: this-3
    question: What happens when you detach a method? const log = obj.log; log();
    answer: this is lost — in non-strict mode it may be the global object; in strict mode undefined. Fix with bind or arrow property.
    difficulty: hard
  - id: this-4
    question: What is the difference between call and apply?
    answer: Both invoke a function with a given this. call takes arguments individually; apply takes an array of arguments.
    difficulty: easy

<TopicDefinition>

**`this`** is a runtime binding that refers to the **execution context** of a function call. It is one of the most misunderstood JavaScript topics — and one of the most tested.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Method vs detached call" language="javascript">
{`const user = {
  name: 'Ada',
  greet() {
    console.log(this.name);
  },
};

user.greet();           // Ada
const fn = user.greet;
fn();                   // undefined (strict) or global name`}
</CodeExample>

<CodeExample title="Arrow functions preserve lexical this" language="javascript">
{`const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds += 1;
      console.log(this.seconds);
    }, 1000);
  },
};`}
</CodeExample>

</TopicTab>

<TopicTab value="indepth">

<Callout type="tip">
In class methods and object literals, regular functions use dynamic `this`. Use arrow functions only when you **want** lexical `this`.
</Callout>
