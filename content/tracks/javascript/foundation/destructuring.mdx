<TopicDefinition>

If someone asks what destructuring is, I'd say it's shorthand for unpacking values into variables — arrays by position, objects by name. Instead of three lines reading `user.name`, `user.age`, `user.city`, you write one pattern that pulls all three out at once.

What interviewers actually probe is the edge cases. Defaults only fire on `undefined`, never on `null` or `0`. And destructuring a missing object throws, while destructuring a missing property just gives `undefined` — so the `= {}` guard at each level is the difference between safe code and a crash.

In senior rounds you might hear about lazy defaults: a default expression only runs when it's needed, so `const { b = expensive() } = { b: 7 }` never calls `expensive()`. Worth knowing when a default does real work.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Arrays match by position" language="javascript">
{`const rgb = ['red', 'green', 'blue'];
const [first, second] = rgb;
console.log(first, second); // red green

// skip with an empty slot, collect the rest
const [head, , third, ...tail] = ['a', 'b', 'c', 'd'];
console.log(head, third, tail); // a c ['d']

// the classic swap — no temp variable
let x = 1, y = 2;
[x, y] = [y, x];
console.log(x, y); // 2 1`}
</CodeExample>

<CodeExample title="Objects match by name: rename and default" language="javascript">
{`const user = { firstName: 'Ada', age: 36, city: 'Paris' };

// colon renames, equals defaults — combined in one pattern
const { firstName: name = 'Guest', age, ...details } = user;
console.log(name, age, details); // Ada 36 { city: 'Paris' }

// rename without a matching property gives undefined, then the default
const { lastName: surname = 'Unknown' } = user;
console.log(surname); // Unknown`}
</CodeExample>

<CodeExample title="Defaults fire only on undefined" language="javascript">
{`const { role = 'guest' } = { role: null };
console.log(role); // null — NOT 'guest'

const { count = 5 } = { count: 0 };
console.log(count); // 0 — a real value, default ignored

// defaults are lazy: this function never runs
let called = false;
const { b = (() => { called = true; return 2; })() } = { b: 7 };
console.log(b, called); // 7 false`}
</CodeExample>

<CodeExample title="Guard each level, including function params" language="javascript">
{`// no address? the = {} guard keeps this from throwing
const user = { name: 'Bob' };
const { address: { city = 'Unknown' } = {} } = user;
console.log(city); // Unknown

// same idea in a function signature — f() must not throw
function greet({ name = 'Guest' } = {}) {
  return 'Hello, ' + name;
}
console.log(greet());        // Hello, Guest
console.log(greet({ name: 'Ada' })); // Hello, Ada`}
</CodeExample>

<TopicTab value="indepth">

<Callout type="gotcha">
Destructuring `null` or `undefined` throws a TypeError, but a missing property is just `undefined`. Guard the source, not just the property: `const { name } = data ?? {}`.
</Callout>

<Callout type="tip">
Two levels of nesting is the practical limit. Past that, the pattern is harder to read than the property access it replaced — pull the middle object out first.
</Callout>

<CodeExample title="Reassigning without declaring needs parens" language="javascript">
{`let a, b;
// { a, b } = { a: 1, b: 2 }; — SyntaxError: { } reads as a block
({ a, b } = { a: 1, b: 2 });
console.log(a, b); // 1 2`}
</CodeExample>
