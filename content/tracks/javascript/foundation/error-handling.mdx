<TopicDefinition>

If someone asks how error handling works in JavaScript, I'd say you wrap the risky code in `try`, handle the failure in `catch`, and put cleanup in `finally`. The error you catch is usually an `Error` object with a `name` and a `message`.

What interviewers actually probe is **timing**. A `try/catch` only catches errors thrown while that block is running. A throw inside `setTimeout`, or a promise rejection nobody awaited, arrives after the block has finished, so the `catch` never sees it. Inside an `async` function the story changes: an awaited rejection behaves just like a throw, so `try/catch` works there.

In senior rounds, expect the **swallow trap**: catching an error and doing nothing with it. The program keeps running, but the real bug is now invisible. Catch what you can handle, rethrow the rest, and give your own errors a clear name so the next person can tell them apart.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="try, catch, finally" language="javascript">
{`function parseAge(input) {
  try {
    const age = JSON.parse(input);
    if (typeof age !== 'number') throw new TypeError('age must be a number');
    return age;
  } catch (error) {
    console.log(error.name + ': ' + error.message);
    return null;
  } finally {
    console.log('parse attempt finished');
  }
}

console.log(parseAge('42'));      // 'parse attempt finished', then 42
console.log(parseAge('"old"'));   // TypeError: age must be a number, 'parse attempt finished', then null`}</CodeExample>

<CodeExample title="The async trap: sync try/catch misses later failures" language="javascript">
{`// This catch NEVER runs: the throw happens after try has finished.
try {
  setTimeout(() => { throw new Error('too late'); }, 0);
} catch (error) {
  console.log('caught');
}
console.log('after try');

// This catch DOES run: await pauses the function until the rejection arrives.
async function load() {
  try {
    await Promise.reject(new Error('boom'));
  } catch (error) {
    console.log('caught: ' + error.message);
  }
}
load();`}</CodeExample>

<CodeExample title="Catch what you can handle, rethrow the rest" language="javascript">
{`class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = 'ValidationError';
  }
}

function saveUser(user) {
  try {
    if (!user.email) throw new ValidationError('email is required');
    return 'saved';
  } catch (error) {
    if (error instanceof ValidationError) {
      console.log('bad input: ' + error.message);
      return null;
    }
    throw error; // anything else is not mine to hide
  }
}

console.log(saveUser({}));            // bad input: email is required, then null
console.log(saveUser({ email: 'a@b.c' })); // 'saved'`}</CodeExample>

<CodeExample title="Promise chains: throw becomes rejection" language="javascript">
{`// A throw inside a .then handler does not crash the chain.
// It turns into a rejection, and the nearest .catch picks it up.
Promise.resolve(10)
  .then((n) => {
    if (n > 5) throw new Error('too big');
    return n;
  })
  .catch((error) => console.log('caught: ' + error.message));
// caught: too big`}</CodeExample>

<TopicTab value="indepth">

<Callout type="gotcha">
A `return` inside `finally` overrides a return from `try` and swallows a throw from `try` or `catch`. Use `finally` for cleanup only, never for returning a value.
</Callout>

<Callout type="tip">
Throw `Error` objects, not strings. A string has no stack trace and no `name`, so the person debugging your code gets nothing to search for. Custom classes like `ValidationError extends Error` keep the stack and add a name worth checking with `instanceof`.
</Callout>

<CodeExample title="finally runs even when try returns" language="javascript">
{`function greet() {
  try {
    return 'hello';
  } finally {
    console.log('cleanup');
  }
}

console.log(greet());
// cleanup
// hello`}</CodeExample>

<CodeExample title="Error types you will meet" language="javascript">
{`console.log(new TypeError('wrong type').name);     // TypeError
console.log(new ReferenceError('no such var').name); // ReferenceError
console.log(new SyntaxError('bad syntax').name);     // SyntaxError
console.log(new RangeError('out of range').name);    // RangeError
// JSON.parse throwing a SyntaxError is the classic interview example.`}</CodeExample>
