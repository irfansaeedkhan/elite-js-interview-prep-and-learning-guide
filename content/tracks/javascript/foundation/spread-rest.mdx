<TopicDefinition>

If someone asks what spread and rest are, I'd say they are the same three dots doing two opposite jobs. Spread expands values out. Rest gathers values in. Which one you get depends entirely on where you write it.

In a function call or a literal, the dots expand. `Math.max(...scores)` turns an array into separate arguments. `{ ...user }` copies an object's properties into a new object. In a parameter list or on the left side of a destructuring, the dots gather. `function sum(...nums)` collects every argument into one real array.

What interviewers usually probe next is the shallow-copy trap. A spread copy is only one level deep. Nested objects are still shared with the original, so editing them through the copy edits the original too. That one fact explains a whole class of state-management bugs.

</TopicDefinition>

<CodeExample title="Spread expands, rest gathers" language="javascript">
{`// Spread: an array becomes separate arguments
const scores = [3, 9, 4];
console.log(Math.max(...scores)); // 9

// Spread: arrays merge into a new array
const merged = [0, ...scores, 10]; // [0, 3, 9, 4, 10]

// Rest: remaining arguments gather into a real array
function sum(...nums) {
  return nums.reduce((total, n) => total + n, 0);
}
console.log(sum(1, 2, 3)); // 6
console.log(sum()); // 0 — rest is an empty array, not undefined`}</CodeExample>

<CodeExample title="The shallow-copy trap" language="javascript">
{`const user = { name: 'Sam', settings: { theme: 'dark' } };
const copy = { ...user };

copy.name = 'Alex'; // safe — top level is copied
console.log(user.name); // 'Sam'

copy.settings.theme = 'light'; // trap — settings is shared
console.log(user.settings.theme); // 'light' — the original changed too

// Fix: spread at every level you change
const fixed = { ...user, settings: { ...user.settings, theme: 'light' } };
console.log(user.settings.theme); // still 'light' from above, fixed is independent`}</CodeExample>

<CodeExample title="Later keys win: defaults plus overrides" language="javascript">
{`const defaults = { theme: 'light', fontSize: 14 };
const userPrefs = { theme: 'dark' };

// Later properties overwrite earlier ones with the same key
const prefs = { ...defaults, ...userPrefs };
console.log(prefs); // { theme: 'dark', fontSize: 14 }

// Rest in destructuring: pull out what you need, keep the rest
const { password, ...safeUser } = { name: 'Sam', password: 'secret', role: 'admin' };
console.log(safeUser); // { name: 'Sam', role: 'admin' }
console.log(password); // 'secret' — still in its own variable`}</CodeExample>

<TopicTab value="indepth">

### Spread in arrays needs an iterable

Array spread works on anything you can loop over with `for...of`: arrays, strings, Sets, Maps. Spreading a plain object or `null` in an array throws a `TypeError`. That is why `[...maybeItems]` is a crash waiting to happen when the data can be missing, and `[...(maybeItems ?? [])]` is the safe form.

### Object spread plays by different rules

Object spread copies an object's own enumerable properties, and it quietly skips `null` and `undefined` sources. So `{ ...maybeOptions }` never throws, even when `maybeOptions` is missing. It also copies symbol-keyed properties, but it reads getters and copies their current value rather than the getter itself.

### Rest is a real array, arguments is not

The old `arguments` object looks like an array but has no `map` or `filter`, and arrow functions do not even get one. A rest parameter is a genuine `Array`, so `nums.reduce(...)` just works. Named parameters before rest are filled first; rest takes only what is left.

### Senior follow-ups

Be ready to explain why `{ ...state, nested: { ...state.nested, field: value } }` is the standard immutable update shape in Redux-style code, and when that nesting gets deep enough that a helper or `structuredClone` is the honest answer instead of hand-spreading five levels.
