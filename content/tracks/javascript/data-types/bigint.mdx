<TopicDefinition>

If someone asks what BigInt is, I'd say it's JavaScript's answer to integers that are too big for the regular Number type. A Number is a 64-bit float, so it only keeps integers exact up to 2^53 − 1. Past that, `Number.MAX_SAFE_INTEGER + 1` and `+ 2` both print `9007199254740992`. BigInt stores arbitrarily large integers exactly — you just add an `n`: `9007199254740993n`.

What interviewers probe most is that BigInt is deliberately **strict**: `1n + 1` throws a TypeError. The engine won't guess whether you wanted a Number or a BigInt result, so you convert one side explicitly first.

In senior rounds, expect the quirks: `JSON.stringify(5n)` throws, `5n / 2n` is `2n` (division truncates), and `Math.sqrt(4n)` throws because Math only takes Numbers. One elegant fix to know: `BigInt.prototype.toJSON` is honored by JSON.stringify, so a tiny prototype patch makes BigInts serializable — one of the rare cases where patching a built-in is officially acceptable.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Where precision dies" language="javascript">
{`const safe = Number.MAX_SAFE_INTEGER; // 9007199254740991
console.log(safe + 1 === safe + 2);   // true — precision lost

const big = BigInt(Number.MAX_SAFE_INTEGER); // 9007199254740991n
console.log(big + 1n); // 9007199254740992n
console.log(big + 2n); // 9007199254740993n — exact`}
</CodeExample>

<CodeExample title="Mixing types throws" language="javascript">
{`// 1n + 1;              // TypeError: can't mix BigInt and Number
console.log(1n + BigInt(1)); // 2n — convert the Number side
console.log(Number(1n) + 1); // 2 — or the BigInt side (loses precision on huge values)
console.log(1n + '2');       // '12' — + with a string still concatenates`}
</CodeExample>

<CodeExample title="Division truncates, unary plus throws" language="javascript">
{`console.log(5n / 2n);   // 2n — truncates toward zero, never 2.5n
console.log(-5n / 2n);  // -2n
// +10n;              // TypeError — no unary plus on BigInt
console.log(-10n);      // -10n — unary minus is fine
console.log(Boolean(0n)); // false — only 0n is falsy`}
</CodeExample>

<CodeExample title="Comparison rules" language="javascript">
{`console.log(0n === 0); // false — strict equality checks the type
console.log(0n == 0);   // true — loose equality converts
console.log(2n > 1);    // true — relational comparisons mix freely
console.log(2n >= 2);   // true

const mixed = [4n, 6, -12n, 10, 4, 0, 0n];
// mixed.sort((a, b) => a - b); // TypeError — subtraction mixes types
mixed.sort((a, b) => (a < b ? -1 : a > b ? 1 : 0)); // safe comparator`}
</CodeExample>

<CodeExample title="JSON serialization" language="javascript">
{`// JSON.stringify({ id: 5n }); // TypeError: BigInt value can't be serialized

const withReplacer = JSON.stringify({ id: 5n }, (key, value) =>
  typeof value === 'bigint' ? value.toString() : value
);
console.log(withReplacer); // {"id":"5"}

// Or patch the one officially tolerated hook:
BigInt.prototype.toJSON = function () { return this.toString(); };
console.log(JSON.stringify({ id: 5n })); // {"id":"5"}`}
</CodeExample>

### Quirks interviewers love

- `typeof 10n === 'bigint'` — it's a primitive, not an object
- `Math.sqrt(4n)` throws — Math methods only accept Numbers
- `4n >>> 2n` throws — unsigned right shift is unsupported; use `>>`
- `BigInt(123.3)` throws RangeError; `BigInt(null)` throws TypeError
- `new BigInt(5)` throws — call it as a function, never with `new`
