<TopicDefinition>

If someone asks what a **symbol** is in JavaScript, I'd say it's a primitive that's guaranteed to be unique — every time you call `Symbol()`, you get a brand-new value, even if you pass the same description string twice. Its main job is giving you object keys that can never collide with anyone else's keys.

What interviewers usually probe next is the **"hidden" behavior**: symbol-keyed properties are skipped by `for..in`, `Object.keys()`, and `JSON.stringify()`, which is why libraries use them to stash metadata on objects. But — and this is the trap — **they're not private**. `Object.getOwnPropertySymbols()` and `Reflect.ownKeys()` find them, and spread and `Object.assign` copy them.

In senior rounds you'll hear about **well-known symbols** like `Symbol.iterator` and `Symbol.toPrimitive` — hooks into the language itself. Implement `[Symbol.iterator]()` on a plain object and it suddenly works with `for..of`. Also worth blurting out once: `new Symbol()` throws. Symbols are never constructed.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Uniqueness and the description trap" language="javascript">
{`const a = Symbol('id');
const b = Symbol('id');

console.log(a === b);  // false — same label, different symbols
console.log(typeof a); // 'symbol'

// new Symbol(); // TypeError: Symbol is not a constructor`}
</CodeExample>

<CodeExample title="Hidden keys that aren't private" language="javascript">
{`const id = Symbol('id');
const user = { name: 'Ada', [id]: 42 };

console.log(Object.keys(user)); // ['name'] — symbol skipped
console.log(JSON.stringify(user)); // '{"name":"Ada"}' — symbol skipped

// ...but not private:
console.log(Object.getOwnPropertySymbols(user)); // [Symbol(id)]
const copy = { ...user };
console.log(copy[id]); // 42 — spread copies symbol keys`}
</CodeExample>

<CodeExample title="A well-known symbol: making an object iterable" language="javascript">
{`const range = {
  from: 1,
  to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  },
};

console.log([...range]); // [1, 2, 3]
for (const n of range) console.log(n); // 1, 2, 3`}
</CodeExample>

<Callout type="interview">
Say it out loud: symbols are **unique**, **hidden from normal enumeration**, but **not private** — and they throw on implicit string conversion.
</Callout>

<TopicTab value="indepth">

<CodeExample title="Symbol.for and the global registry" language="javascript">
{`const s1 = Symbol.for('app-id');
const s2 = Symbol.for('app-id');

console.log(s1 === s2);               // true — same registry entry
console.log(Symbol('app-id') === s1); // false — Symbol() is always new
console.log(Symbol.keyFor(s1));      // 'app-id' — the inverse lookup`}
</CodeExample>

<CodeExample title="Symbol.toPrimitive: custom type conversion" language="javascript">
{`const money = {
  amount: 99,
  [Symbol.toPrimitive](hint) {
    return hint === 'number' ? this.amount : \`$\${this.amount}\`;
  },
};

console.log(+money);     // 99 — number hint
console.log(\`\${money}\`); // '$99' — string hint`}
</CodeExample>

<CodeExample title="The string-conversion trap" language="javascript">
{`const sym = Symbol('id');

// \`\${sym}\`; // TypeError: Cannot convert a Symbol value to a string
// 'id: ' + sym; // TypeError — same for +

console.log(String(sym));     // 'Symbol(id)' — explicit is fine
console.log(sym.description); // 'id' — just the label`}
</CodeExample>

### Senior follow-ups

Be ready to say when **not** to use symbols: overusing them makes objects hard to inspect in the debugger, and because symbol keys silently vanish from `JSON.stringify`, data can be lost when an object crosses an API boundary — serialize deliberately.
