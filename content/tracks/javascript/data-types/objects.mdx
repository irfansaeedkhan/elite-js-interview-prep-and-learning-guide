<TopicDefinition>

If someone asks what an object is in JavaScript, I'd say it's a bag of key-value pairs — `{}` — the structure behind most data you'll touch. Arrays, functions, even classes are objects with extras.

What interviewers actually probe is the **reference model**: a variable doesn't hold the object, it holds a pointer to it. So `const b = a` doesn't copy anything — both names point at the same bag, and mutating through one name shows up through the other. That's the setup for every clone question.

In senior rounds they go one level deeper: keys coerce to strings, integer-like keys enumerate out of order, and `{...obj}` plus `Object.freeze` are both shallow. Each of those is a trap disguised as a follow-up.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Reference vs value" language="javascript">
{`const a = { count: 1 };
const b = a;          // copies the pointer, not the object
b.count = 2;
console.log(a.count); // 2 — same object

const c = { ...a };
c.count = 99;
console.log(a.count); // 2 — shallow copy of the top level`}
</CodeExample>

<CodeExample title="Key coercion trap" language="javascript">
{`const o = {};
o[1] = 'one';         // key becomes the string '1'
o['1'] = 'ONE';       // same key — overwrites!
console.log(o[1]);    // 'ONE'

const key = { toString: () => 'k' };
const obj = { [key]: 'value' };
console.log(obj.k);   // 'value' — computed key was coerced too`}
</CodeExample>

<CodeExample title="Shallow clone and shallow freeze" language="javascript">
{`const user = { name: 'Ada', profile: { level: 1 } };
const copy = { ...user };
copy.profile.level = 99;
console.log(user.profile.level); // 99 — nested object is shared

const frozen = Object.freeze({ ...user });
frozen.name = 'Grace';            // silently ignored (strict mode throws)
frozen.profile.level = 1;        // works — freeze is shallow too`}
</CodeExample>

<CodeExample title="Optional chaining and nullish coalescing" language="javascript">
{`const user = { profile: { name: 'Ada' }, retries: 0 };
console.log(user?.profile?.name);            // 'Ada'
console.log(user?.settings?.theme ?? 'dark');// 'dark' — missing, so fallback
console.log(user.retries ?? 3);              // 0 — ?? keeps falsy-but-valid values
console.log(user.retries || 3);              // 3 — || would swallow the 0`}
</CodeExample>

</TopicTab>

<TopicTab value="indepth">

<Callout type="gotcha">
`obj.__proto__ = {...}` doesn't add a key — it **changes the prototype**. That's the prototype-pollution trap. For a safe dictionary with no inherited keys, use `Object.create(null)` or a `Map`.
</Callout>

<Callout type="tip">
`structuredClone(obj)` is the modern deep clone — it handles Dates, RegExps, Maps, and circular references. But it throws on functions, so don't use it on objects with methods.
</Callout>

<CodeExample title="Enumeration order" language="javascript">
{`console.log(Object.keys({ b: 1, 10: 2, a: 3 }));
// ['10', 'b', 'a'] — integer-like keys first, ascending,
// then string keys in insertion order`}</CodeExample>

<CodeExample title="in vs hasOwnProperty" language="javascript">
{`const o = { name: 'Ada' };
console.log('name' in o);                    // true — own key
console.log('toString' in o);                // true — inherited, still counts
console.log(o.hasOwnProperty('toString'));   // false — own keys only`}
</CodeExample>
