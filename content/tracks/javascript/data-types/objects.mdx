<TopicDefinition>

An **object** is a collection of properties — keys mapped to values. Arrays and functions are objects too, but plain objects `{}` are the workhorse for structured data.

Objects are **reference types**: variables hold pointers, not the object itself.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Reference vs value" language="javascript">
{`const a = { count: 1 };
const b = a;
b.count = 2;
console.log(a.count); // 2 — same object

const c = { ...a };
c.count = 99;
console.log(a.count); // 2 — shallow copy`}
</CodeExample>

<CodeExample title="Optional chaining and nullish coalescing" language="javascript">
{`const user = { profile: { name: 'Ada' } };
console.log(user?.profile?.name);     // Ada
console.log(user?.settings?.theme);   // undefined
console.log(user?.settings?.theme ?? 'dark'); // dark`}
</CodeExample>

</TopicTab>

<TopicTab value="indepth">

<Callout type="tip">
Prefer `const` for object bindings — you cannot reassign the variable, but you **can** mutate properties.
</Callout>

### Common patterns

- `Object.keys(obj)` — own enumerable keys
- `Object.entries(obj)` — `[key, value]` pairs
- `structuredClone(obj)` — deep clone (modern environments)
