<TopicDefinition>

If someone asks me about `null` vs `undefined`, I'd say they are JavaScript's two flavors of "nothing" — and they mean different things. `null` is a **decision**: I assigned it to mean "there is intentionally no value here," like a user lookup that found no user. `undefined` is a **default state**: JavaScript's way of saying "not set yet" — a declared variable you never assigned, a function argument nobody passed, a property that doesn't exist, or a function that returned nothing.

Interviewers care about this topic because it's a **trap factory**. `typeof null` says `'object'` — a 1995 bug that can never be fixed without breaking the web. `null == undefined` is true but `null === undefined` is false. `Number(null)` is `0` while `Number(undefined)` is `NaN`. And the default-value question separates juniors from seniors: `||` falls back on **any** falsy value, while `??` only falls back on null and undefined.

Senior rounds sometimes probe the **`typeof` guard**: `typeof someVar === 'undefined'` doesn't throw even when `someVar` was never declared, which is why old code used it to feature-detect globals before optional chaining existed.

</TopicDefinition>

<CodeExample title="Where each one shows up" language="javascript">
{`// undefined — JavaScript assigns it, you usually don't
let name;
console.log(name);            // undefined (declared, not assigned)

function greet(user) { return user; }
console.log(greet());         // undefined (missing argument)

console.log({}.missingKey);   // undefined (missing property)

// null — you assign it on purpose
let currentUser = null;       // "we checked, there is no user"
console.log(typeof currentUser); // "object" — the famous 1995 bug
console.log(typeof undefined);   // "undefined"`}
</CodeExample>

<CodeExample title="The equality and conversion traps" language="javascript">
{`// == treats them as equal, === does not
console.log(null == undefined);   // true  (loose — the one == most teams allow)
console.log(null === undefined);  // false (strict — different types)

// They convert differently
console.log(Number(null));        // 0
console.log(Number(undefined));   // NaN
console.log(Boolean(null));       // false
console.log(Boolean(undefined));  // false

// Neither one autoboxes — no method calls
// null.toString();      // TypeError
// undefined.toString(); // TypeError`}
</CodeExample>

<CodeExample title="?? vs || — the default-value trap" language="javascript">
{`function withTimeout(timeout) {
  const withOr = timeout || 5000;   // 0 becomes 5000 — wrong if 0 is valid!
  const withNullish = timeout ?? 5000; // 0 stays 0, null/undefined become 5000
  return [withOr, withNullish];
}

console.log(withTimeout(0));         // [5000, 0]
console.log(withTimeout(undefined)); // [5000, 5000]

// ?. short-circuits on null OR undefined
const user = null;
console.log(user?.profile?.name ?? 'anonymous'); // "anonymous"`}
</CodeExample>

<TopicTab value="indepth">

### What to focus on

- The mental model: `null` is an assigned "nothing," `undefined` is the language's "not set yet"
- The three classic traps: `typeof null === 'object'`, `null == undefined` vs `===`, and `??` vs `||` for defaults
- The `typeof` guard: safe on undeclared variables where direct comparison throws

### When to use null

- A function result meaning "looked, found nothing" (`findUser()` returns `null`)
- Resetting state to a known empty: `selection = null`
- APIs that distinguish "absent" from "never provided"

### Senior follow-ups

Be ready to explain why `undefined` shouldn't be **assigned** explicitly (prefer leaving things unset or using `null`), the `void 0` idiom from minified code, and how `?.` and `??` work together as the modern null-safe pattern.

</TopicTab>
