<TopicDefinition>

JavaScript has one numeric type: **IEEE 754 double-precision floating point**. There is no separate int type — `42` and `42.5` share the same type.

Interviewers love **NaN**, **Infinity**, and **floating-point precision** questions.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Floating-point precision" language="javascript">
{`console.log(0.1 + 0.2);              // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);      // false
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true`}
</CodeExample>

<CodeExample title="NaN and parsing" language="javascript">
{`console.log(NaN === NaN);           // false
console.log(Number.isNaN(NaN));     // true
console.log(parseInt('42px', 10));  // 42
console.log(Number('42px'));        // NaN`}
</CodeExample>

</TopicTab>

<TopicTab value="indepth">

<Callout type="gotcha">
`typeof NaN` is `'number'`. NaN poisons arithmetic — any operation with NaN yields NaN.
</Callout>

<CodeExample title="BigInt for large integers" language="javascript">
{`const big = 9007199254740991n;
console.log(big + 1n); // 9007199254740992n`}
</CodeExample>
