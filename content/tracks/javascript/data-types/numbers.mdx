<TopicDefinition>

If someone asks how numbers work in JavaScript, I'd say there's only **one** number type: a 64-bit float. There is no separate int — `42` and `42.5` are the same type, which is why decimal math can surprise you.

Interviewers almost always follow up with **`0.1 + 0.2`** or **NaN**. Binary can't store 0.1 exactly — like 1/3 in decimal, it repeats forever — so the sum lands at `0.30000000000000004`. And NaN is the only value in the language that isn't equal to itself.

In senior rounds you might hear about **`Number.EPSILON`**: it's the smallest step a double can take near 1, not a general-purpose comparison tolerance. Fine for numbers under 1; misleading for millions. And past **`Number.MAX_SAFE_INTEGER`**, integers start rounding too — that's what BigInt is for.

</TopicDefinition>

<TopicTab value="examples">

<CodeExample title="Floating-point precision" language="javascript">
{`console.log(0.1 + 0.2);                      // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);              // false
// safe pattern: pick your own tolerance
console.log(Math.abs(0.1 + 0.2 - 0.3) < 1e-10); // true`}
</CodeExample>

<CodeExample title="The Number.EPSILON trap" language="javascript">
{`// EPSILON is the smallest step near 1 — not a general tolerance
const close = (a, b) => Math.abs(a - b) < Number.EPSILON;

console.log(close(0.1 + 0.2, 0.3));              // true — looks safe
console.log(close(1000000.1 + 0.2, 1000000.3));  // false — tolerance too tight
// floats have ~15 significant digits; the gap scales with size`}</CodeExample>

<CodeExample title="Safe integers" language="javascript">
{`console.log(Number.MAX_SAFE_INTEGER);                    // 9007199254740991
console.log(Number.MAX_SAFE_INTEGER + 1 ===
            Number.MAX_SAFE_INTEGER + 2);                // true (!)
console.log(9007199254740992 === 9007199254740993);      // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1)); // false`}
</CodeExample>

<CodeExample title="NaN and parsing" language="javascript">
{`console.log(NaN === NaN);            // false — NaN equals nothing
console.log(isNaN('hello'));          // true — global isNaN coerces first
console.log(Number.isNaN('hello'));   // false — no coercion
console.log(parseInt('42px', 10));    // 42 — parses leading digits
console.log(Number('42px'));          // NaN — strict conversion`}
</CodeExample>

<TopicTab value="indepth">

<Callout type="gotcha">
`typeof NaN` is `'number'`. NaN poisons arithmetic — any operation with NaN yields NaN.
</Callout>

<Callout type="tip">
Money rule: store cents as integers, not dollars as floats. `0.1 + 0.2` dollars is 30.000000000000004 cents of trouble.
</Callout>

<CodeExample title="BigInt for large integers" language="javascript">
{`const big = 9007199254740991n;
console.log(big + 1n); // 9007199254740992n
// console.log(big + 1); — TypeError: can't mix BigInt and Number`}</CodeExample>

<CodeExample title="toFixed returns a string" language="javascript">
{`const price = (19.99).toFixed(2);
console.log(price);        // '19.99' — a string, not a number
console.log(price + 1);    // '19.991' — concatenation, not addition
console.log(+price + 1);   // 20.99`}
</CodeExample>
