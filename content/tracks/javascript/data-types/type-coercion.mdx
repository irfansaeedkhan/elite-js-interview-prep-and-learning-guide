<TopicDefinition>

If someone asks what type coercion is, I'd say: JavaScript converts values between types automatically when an operator needs it to. You never called `Number()` — the operator did it on your behalf.

The mental model that makes the weird stuff predictable: **the operator decides the target type**. `+` says "string if I see one, otherwise numbers." `-`, `*`, `/`, and `<` say "numbers, always." `if`, `&&`, and `!` say "booleans." Once you know what the operator wants, the result stops being magic.

Interviewers probe the two places this bites: objects turning into primitives (`valueOf`/`toString`, hint order) and the falsy list. Nail those and every "trick question" is just arithmetic.

</TopicDefinition>

<CodeExample title="The + split personality" language="javascript">
{`'5' + 3;      // '53' — + concatenates if either side is a string
'5' - 3;      // 2 — minus always converts to numbers first
'5' * '2';    // 10 — both strings become numbers
true + true;  // 2 — booleans become 1 and 1

// Evaluation is left to right — the string "infects" what follows:
1 + '2' + 3;  // '123' — (1 + '2') is '12', then '12' + 3
1 + 2 + '3';  // '33'  — (1 + 2) is 3, then 3 + '3'`}
</CodeExample>

<CodeExample title="Objects to primitives" language="javascript">
{`// A plain object's valueOf returns the object itself (not a
// primitive), so it falls through to toString:
String({});   // '[object Object]'
String([1, 2]); // '1,2' — arrays join with commas
String([]);   // '' — empty array becomes the empty string

// That's the whole story behind the classics:
[] + [];      // '' — '' + ''
[] + {};      // '[object Object]' — '' + '[object Object]'`}
</CodeExample>

<CodeExample title="Boolean coercion: the falsy list" language="javascript">
{`Boolean('');        // false
Boolean('hello');   // true — any non-empty string is truthy
Boolean([]);        // true — objects are NEVER falsy
Boolean({});        // true
Boolean(0n);        // false — BigInt zero is falsy, like 0

if ([]) {
  // this runs — [] is truthy, a classic interview gotcha
}`}
</CodeExample>

### ToPrimitive: the order that decides everything

Whenever an operator needs a primitive from an object, JavaScript runs `ToPrimitive` with one of three hints. The hint picks the method order — and the first method returning a primitive wins:

- **"string"** — template literals, `String()`: `Symbol.toPrimitive` → `toString` → `valueOf`
- **"number"** — unary `+`, `Number()`, `-`: `Symbol.toPrimitive` → `valueOf` → `toString`
- **"default"** — binary `+`, `==`: `Symbol.toPrimitive` → `valueOf` → `toString`

The one exception: **Date** treats `"default"` as `"string"`, which is why `new Date(0) + 1` concatenates instead of adding.

<CodeExample title="Hint order in action" language="javascript">
{`const weird = {
  valueOf() { return 10; },
  toString() { return 'twenty'; },
};

String(weird);  // 'twenty' — 'string' hint tries toString first
+weird;         // 10 — 'number' hint tries valueOf first
weird + 5;      // 15 — 'default' hint tries valueOf first`}
</CodeExample>

<CodeExample title="Symbol.toPrimitive overrides everything" language="javascript">
{`const price = {
  amount: 1000,
  currency: 'USD',
  [Symbol.toPrimitive](hint) {
    if (hint === 'string') return this.amount + ' ' + this.currency;
    return this.amount; // 'number' and 'default'
  },
};

String(price);  // '1000 USD'
+price;         // 1000
price + 50;     // 1050`}
</CodeExample>

### The console trap: {} + []

Type `{} + []` in a console and you get `0`, not `'[object Object]'`. That's not coercion — it's parsing. At the start of a statement, `{}` is read as an empty **block**, so the engine only sees `+[]`: unary plus on `[]`, which ToPrimitives to `''`, then to `0`. Wrap it in parentheses — `({} + [])` — and the object survives: `'[object Object]'`.

### Senior follow-ups

Be ready to say when **not** to lean on coercion. At system boundaries — API payloads, form values, URL params — convert explicitly: `Number(input)`, `String(id)`. Implicit coercion stays readable only for the idioms everyone recognizes: `!!value` for booleans, `+str` for numbers, `value ?? fallback` instead of `||` when `0` and `''` are valid.

And know the famous applied-coercion interview question: a chainable `add(1)(2)(3)` that coerces to its running total. It's in the playground below — implementing it with `Symbol.toPrimitive` is the difference between reciting the rules and using them.
