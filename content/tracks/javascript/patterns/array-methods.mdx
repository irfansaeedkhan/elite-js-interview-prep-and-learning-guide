<TopicDefinition>

If someone asks me about array methods, I'd say almost every one of them answers one of three questions: transform every element (`map`), keep only some (`filter`), or boil the whole array down to one value (`reduce`). Once you know which question you're asking, the method picks itself — and chaining them reads like a sentence: filter the adults, map to their names.

Interviewers care about this topic because it's where the **mutation fault line** runs. `map`, `filter`, and `slice` hand you something new and leave the original alone. `sort`, `splice`, `reverse`, and `push` rewrite the array in place — and `sort` is the sneakiest of the lot, because it returns the same array reference, so `const sorted = items.sort()` looks like a copy and isn't.

Senior rounds push past the names into the edges: the default sort compares **strings**, so `[10, 9, 80].sort()` gives `[10, 80, 9]`; `reduce` with no seed throws on an empty array; and `map` skips holes in sparse arrays instead of calling your function for them.

</TopicDefinition>

<CodeExample title="map, filter, reduce — the big three" language="javascript">
{`const users = [
  { name: 'Aya', age: 17 },
  { name: 'Ben', age: 24 },
  { name: 'Cid', age: 31 },
];

// transform every element — same length out
console.log(users.map((u) => u.name));           // ['Aya', 'Ben', 'Cid']

// keep only some — shorter array out
console.log(users.filter((u) => u.age >= 18));   // [Ben, Cid]

// fold to one value — a single number out
console.log(users.reduce((sum, u) => sum + u.age, 0)); // 72

// chaining reads like a sentence: filter, then transform
console.log(
  users.filter((u) => u.age >= 18).map((u) => u.name),
); // ['Ben', 'Cid']`}
</CodeExample>

<CodeExample title="The mutation fault line" language="javascript">
{`const scores = [3, 1, 2];

// sort MUTATES and returns the SAME reference — not a copy
const sorted = scores.sort();
console.log(sorted === scores); // true — same array, reordered
console.log(scores);            // [1, 2, 3] — the original is gone

// slice vs splice: one copies, one cuts
const letters = ['a', 'b', 'c', 'd'];
console.log(letters.slice(1, 3)); // ['b', 'c'] — original untouched
console.log(letters.splice(1, 2)); // ['b', 'c'] — removed FROM letters
console.log(letters);              // ['a', 'd']

// ES2023 copying methods — the mutating jobs, without the mutation
const nums = [3, 1, 2];
console.log(nums.toSorted());   // [1, 2, 3]
console.log(nums);              // [3, 1, 2] — still the original order`}
</CodeExample>

<CodeExample title="The default sort trap" language="javascript">
{`// no comparator: elements become strings, then compare
console.log([10, 9, 80].sort()); // [10, 80, 9] — '10' < '80' as strings

// always pass a comparator for numbers
console.log([10, 9, 80].sort((a, b) => a - b)); // [9, 10, 80]

// the comparator contract: negative → a first, positive → b first
const people = [{ name: 'Zed', age: 40 }, { name: 'Ana', age: 22 }];
console.log(people.sort((a, b) => a.age - b.age));
// [{ name: 'Ana', age: 22 }, { name: 'Zed', age: 40 }]`}
</CodeExample>

<CodeExample title="reduce: the seed matters" language="javascript">
{`// no initial value: first element becomes the seed
console.log([1, 2, 3].reduce((sum, n) => sum + n)); // 6

// empty array with no seed: nothing to seed from
// [].reduce((sum, n) => sum + n); // TypeError: reduce of empty array with no initial value

// always pass a seed — the empty case just returns it
console.log([].reduce((sum, n) => sum + n, 0)); // 0

// reduce is the escape hatch: group by a key in one pass
const orders = [
  { dept: 'web', amount: 50 },
  { dept: 'api', amount: 30 },
  { dept: 'web', amount: 20 },
];
console.log(
  orders.reduce((groups, o) => {
    groups[o.dept] = (groups[o.dept] ?? 0) + o.amount;
    return groups;
  }, {}),
); // { web: 70, api: 30 }`}
</CodeExample>

<Callout type="gotcha">
`forEach` returns `undefined` and you cannot `break` out of it. If you need an early exit, use a `for...of` loop or `find`/`some`/`every` — and never use `map` just for side effects; a discarded return value is a code smell.
</Callout>

<TopicTab value="indepth">

### Which method for which job

- **Transform every element** — `map` (same length out, new array)
- **Keep only some** — `filter` (shorter array out, new array)
- **First match / does one exist / do all pass** — `find` / `some` / `every`
- **One value from many** — `reduce`, always with an initial value
- **Flatten one level, or map then flatten** — `flat` / `flatMap`
- **Reorder or patch without mutating** — `toSorted` / `toReversed` / `toSpliced` / `with`

### Senior follow-ups

Be ready to **implement `map`, `filter`, or `reduce` by hand** — interviewers ask for it to test whether you understand callbacks and accumulation, not the method names. The checks they run: holes stay holes, the original is untouched, the callback gets `(value, index, array)`, and the optional `thisArg` is honored.

Know the **sparse-array split**: `map`, `filter`, and `forEach` skip empty slots entirely, while `find` and `includes` treat holes as `undefined`. A hole is not the same as an explicit `undefined` — `[1, , 3].length` is 3, but the callback only runs twice.

And watch the **chaining cost**: `filter` then `map` walks the array twice and builds an intermediate array. On a hot path over a huge list, one `reduce` (or a plain `for` loop) does it in a single pass — say that out loud before reaching for it, because readability usually wins.
